## v0.1 Architecture

v0.1 冻结 Phase 1–4 已验证语义：Component/Capability/Requirement、prepare 与
activation 生命周期分离、EffectScope LIFO teardown、activation 拥有 capability、
critical task failure 撤销 activation、Composer failure 不等于 provider failure、
snapshot reconstruction、物理 `CapabilityInstanceId`、完整
`MessageTypeDescriptor`/`LayoutHash`、fixed/slice message shape、Sensor/Control
profile，以及 Rust/C++ 原生共享内存数据路径。Composer 只处于 composition plane，
payload 不经过 Composer。

版本轴已经独立：

| 版本轴 | v0.1 值 |
| --- | ---: |
| SDK | `0.1.0` |
| IDL language | `1` |
| Message descriptor format | `1` |
| Control protocol | `2` |
| Composer snapshot | `1` |

HELLO 同时携带 control/snapshot version；不匹配时 Composer 返回明确的
`ProtocolMismatch`。生成器与 SDK 版本不进入 layout hash。Rust/C++ 生成文件具有
四行稳定 header，不包含时间、绝对路径、主机名或随机值；两次生成以及与 checked-in
artifact 的逐字节 diff 均为空。

## Public Rust API

应用的稳定入口是 `rbt` facade：

- `rbt::component`：`Component`、`ActivationCtx`、`EffectScope`、task 与 runner；
- `rbt::stream`：fixed/slice stream、publisher/subscriber、loan/receive guard；
- `rbt::types`：capability/requirement/identity/descriptor 与生成消息；
- `rbt::control`：Composer server 和两个 control version 常量；
- `rbt::prelude`：只导出 `Component`、`ActivationCtx`、`Capability`、
  `Requirement`、`Stream`、`StreamProfile`、`Result`。

`RbtError` 保存 component、requirement、stream、control-plane 子系统的 typed source；
library public boundary 不暴露 `anyhow::Error`。底层 workspace crate 仍可供高级使用，
但未被 facade 重导出的 surface 明确视为 runtime/internal 0.x surface。

最小 provider 形状如下；完整可运行版本是
`examples/rust/camera/src/main.rs`：

```rust
#[async_trait]
impl Component for CameraA {
    type Config = ();
    type Error = anyhow::Error;

    async fn prepare(_: &Self::Config) -> Result<Self, Self::Error> {
        Ok(Self)
    }

    fn id(&self) -> ComponentId { ComponentId::from("camera-a") }
    fn requirements(&self) -> Vec<RequirementSpec> { Vec::new() }

    async fn activate(&mut self, ctx: &mut ActivationCtx<'_>) -> Result<(), Self::Error> {
        let id = CapabilityInstanceId::new();
        let descriptor = SliceStream::<Image>::descriptor(
            id.stream_service_name(), StreamProfile::Sensor);
        let publisher = SliceStream::<Image>::publisher(&descriptor, 64)?;
        ctx.provide::<Camera>(id, descriptor);
        ctx.spawn_critical("publish", move |stop| async move {
            let mut sequence = 1_u64;
            let mut tick = tokio::time::interval(Duration::from_millis(100));
            loop {
                tokio::select! {
                    _ = stop.cancelled() => return Ok::<(), anyhow::Error>(()),
                    _ = tick.tick() => {
                        let mut sample = publisher.loan_slice(64)?;
                        sample.header_mut().sequence = sequence;
                        sample.payload_mut().fill(0xA1);
                        sample.send()?;
                        sequence += 1;
                    }
                }
            }
        });
        Ok(())
    }
}
```

## C++ Component SDK

安装 SDK 提供 `rbt/runtime.hpp`、`effect_scope.hpp`、`stream.hpp`、`types.hpp`、
`version.hpp` 和生成消息头，以及链接库 `librbt_runtime.a`。真实 detector 位于
`examples/cpp/detector/main.cpp`，其核心形状是：

```cpp
class Detector final : public rbt::Component {
  public:
    rbt::Result<void> prepare() override {
        model_id_ = 1U;              // process-lifetime work
        return {};
    }

    rbt::Result<void> activate(rbt::ActivationContext& context) override {
        auto camera = context.require<Camera>("camera");
        if (!camera) return rbt::Result<void>::failure(camera.error());
        auto subscriber =
            camera.slice_subscriber<rbt::sensor::ImageHeader, std::uint8_t>();
        if (!subscriber) return rbt::Result<void>(subscriber.error());

        const auto capability = rbt::generate_uuid();
        const auto stream = rbt::OwnedStreamDescriptor::from(
            rbt::StreamDescriptor("rbt/cap/" + capability + "/stream",
                                  rbt::demo::DETECTION_DESCRIPTOR,
                                  rbt::StreamProfile::Sensor));
        auto publisher = rbt::FixedPublisher<rbt::demo::Detection>::create(
            stream.borrowed(), rbt::demo::DETECTION_DESCRIPTOR);
        if (!publisher) return rbt::Result<void>(publisher.error());
        auto provided = context.provide<Detections>(capability, stream);
        if (!provided) return rbt::Result<void>::failure("provide failed");

        context.spawn_critical(
            "inference",
            [subscriber = std::move(subscriber).value(),
             publisher = std::move(publisher).value()]
            (std::stop_token stop) mutable {
                while (!stop.stop_requested()) {
                    auto image = subscriber.receive();
                    if (!image) return rbt::TaskOutcome::error("receive failed");
                    if (!image.value().has_value()) {
                        std::this_thread::sleep_for(std::chrono::milliseconds(10));
                        continue;
                    }
                    const auto sequence = image.value()->header().sequence;
                    const auto payload = image.value()->payload();
                    const auto value = payload.empty() ? 0U : payload.front() * 10U;
                    image.value().reset();

                    auto detection = publisher.loan();
                    if (!detection) return rbt::TaskOutcome::error("loan failed");
                    detection.value().payload().sequence = sequence;
                    detection.value().payload().value = value;
                    if (!detection.value().send()) {
                        return rbt::TaskOutcome::error("send failed");
                    }
                }
                return rbt::TaskOutcome::completed();
            });
        return {};
    }

  private:
    std::uint64_t model_id_ { 0U };
};
```

`prepare()` 每进程一次；每次 activation 获得完整 binding 和新 ActivationId。
EffectScope 显式 `shutdown()`，请求 stop、join 所有 `std::jthread`，再严格 LIFO
执行 cleanup；destructor 只是 safety net。critical/background task 在 thread boundary
捕获异常并生成携带 ProcessInstanceId/ActivationId 的 `TaskEvent`；旧 activation event
被忽略。Control client 使用同一 TCP+NDJSON schema，发送 HELLO/完整 snapshot，按
`100/200/500/1000 ms` bounded backoff 重连，并在 Composer outage 时保留健康 activation。

ownership 审计未发现 detached thread、owning raw pointer、裸 `new/delete` 或脱离
receive guard 的 owning span。loan/receive sample 和 endpoint 都是 non-copyable、
move-only RAII owner。

## Mixed-language composition

最终实际链路为：

```text
Rust Camera -- Camera / rbt.sensor/Image@1 --> C++ Detector
            -- Detections / rbt.demo/Detection@1 --> Rust Viewer
```

`scripts/test_mixed_runtime.sh` 的最终运行目录是
`target/v01-logs/mixed.E4V73w`。初始 CLI graph 为：

```text
camera-a -[camera:Camera]-> detector
detector -[detections:Detections]-> viewer
```

kill Camera A 后，`rbt why detector` 报告 `detector is BLOCKED`、原因
`Camera provider disappeared`，并保留 last-active provider/capability。启动 Camera B
后，同一 C++ detector process
`568f1d23-02f9-43b0-8255-4580b8ec11d9` 从 activation `1` 进入 `2`，其 Detections
capability 从 `68fde24d-5a4c-4093-8319-d880ff416932` 换为
`59b473b4-c5dd-4c90-96a8-6ff33e8e284c`，而 `model_loads=1`。

随后以 `RBT_TEST_FAIL_AFTER=3` 注入 C++ inference critical-task failure。实际结果为
Detections capability 被撤销、viewer BLOCKED；`rbt why detector` 给出
`critical task inference exited: test failure after processing 3 frames`，并列出最后的
Camera binding。

## Benchmark harness

`scripts/benchmark_v01.sh` 为同机双进程 publisher→subscriber harness，使用真实生成
Image、PointCloud、ControlCommand ABI；不经过 Composer、不序列化、不插入临时
payload buffer。publisher 在 send 前写 sequence/timestamp，subscriber 用同一主机时钟
计算 nearest-rank p50/p90/p99/max；同时记录 publish/receive rate、CPU time、RSS、
drop、layout hash、queue 配置与完整环境。Sensor 为 depth 1 + safe overflow，Control
为 depth 4 + no safe overflow/QueueFull retry。

最终保存的 release run 是 `target/v01-logs/benchmark-full-final.log`：Intel Core Ultra
5 125H、18 logical CPUs、Ubuntu 26.04、Linux 7.0.0-30、rustc 1.98.1、GCC 15.2.0，
20 measured + 3 warmup，1 subscriber，1 ms pacing。所有 case 20/20 received、0 drop。

本基线的 Rust unsafe 审计计得 31 个 production source locations：1 个 `ShmSafe` unsafe trait
契约、10 个固定 primitive impl、18 个 generated ABI/iceoryx2 impl、2 个只读 Linux
`clock_gettime`/`sysconf` 调用；每处都有相邻 SAFETY 说明。另有 12 个 test/mismatch
fixture impl，同样有 SAFETY 说明。IDL generator 中出现的 `unsafe` 字符串是生成模板，
不是 generator 的 executable unsafe（该 crate `forbid(unsafe_code)`）。

Pressure milestone 复核仍为同样的 31 个 production locations，因此相对本基线的
unsafe count delta 为 `0`；pressure counters、snapshot、CLI、测试 helper 与 C++
receiver-port diagnostics 没有新增 Rust unsafe。

## Breaking changes

没有 Phase 1–4 frozen semantic change。v0.1 对 spike-era surface 做的是 facade、显式版本
字段、稳定 generated header、typed error、诊断和安装边界收敛；既有 layout hash、
ownership、lifecycle、backpressure 和 recovery 语义保持不变。
