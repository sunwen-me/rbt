# IDL and deterministic generation

`rbt-idl` defines the local shared-memory schema subset used by both SDKs. It
is a layout compiler, not a network serialization compiler.

For an application project, use the project-aware entry point so source roots,
output directories, and the generation manifest stay consistent:

```bash
rbt idl check
rbt idl fmt
rbt idl fmt --check
rbt idl generate
```

The standalone `rbt-idl` binary remains useful for backend-focused or
repository fixture work. It does not discover `rbt.toml`.

## v1 language

Every file declares one dotted package and one ABI major:

```text
package robot.vision;
abi 1;
```

The v1 declarations are:

- `newtype Name: <integer> { Variant = value; ... }`
- `struct Name { field: type; fixed: u8[7]; ... }`
- fixed `message Name { ... }`
- slice `message Name = slice { header Header; payload Element[]; }`

Supported scalars are fixed-width integers and floats. Named fields may refer
to local structs/newtypes; fixed arrays are supported where the v1 validator
allows them. Empty structs/messages, recursive structs, unknown types,
ambiguous generated names, backend keywords, nested arrays, and array slice
elements are rejected before generation.

Examples are in `types/demo.rbt`, `types/sensor.rbt`, `types/control.rbt`, and
`types/tf.rbt`.

The repository production generation set is exactly `types/sensor.rbt`,
`types/control.rbt`, `types/demo.rbt`, and `types/tf.rbt`. There is no
production `types/time.rbt` or `types/rpc.rbt`. Files under `types/fixtures/`
are generated separately for validation and are not production inputs.

## Generate

```bash
rbt-idl generate robot.rbt \
  --rust generated/rust \
  --cpp generated/cpp \
  --descriptor generated/descriptors \
  --python python/rbt/_generated
```

Multiple input files may precede the output flags. Each schema produces a Rust
module, a C++ header below its package namespace, descriptor JSON, and optional
Python descriptor/dtype metadata. The Python target does not generate a
runtime. Generated files begin with the stable header:

```text
// @generated by rbt-idl; deterministic output.
// IDL language version: 1
// Message descriptor format version: 1
// DO NOT EDIT.
```

There are no timestamps, hostnames, absolute input paths, random values, or
directory-dependent strings in generated output. The historical `verify_v01`
gate generates twice, compares each backend byte-for-byte, and compares the
result with the checked-in tree.

## Namespaces and descriptors

Rust output is included by `rbt-types`; C++ output uses nested namespaces such
as `rbt::sensor`. Each message exposes shape, ABI major, sizes/alignments,
canonical field signature, and a 128-bit layout hash. Descriptor JSON records
`idl_language_version` and `message_descriptor_version` independently.

The generator/SDK version is intentionally absent from the hash input. See
`abi.md` for the canonical envelope and compatibility rule.

## Diagnostics

Parser and semantic errors include a stable path, one-based line/column, source
line, and caret. For example:

```text
recursive.rbt:4:5: recursive struct type: Node -> Node
  Node child;
  ^
```

The compiler does not turn malformed input into an unwrap/panic diagnostic.
Fix the first structural error and rerun generation; later offsets can depend
on earlier declarations.

## Checked-in outputs

Do not edit generated artifacts by hand. Regenerate the current production set
with:

```bash
cargo run -p rbt-idl -- generate \
  types/sensor.rbt types/control.rbt types/demo.rbt types/tf.rbt \
  --rust generated/rust \
  --cpp generated/cpp \
  --descriptor generated/descriptors \
  --python python/rbt/_generated
```

`generated/mismatch` comes from `types/fixtures/image_mismatch.rbt` and exists
only to prove preflight `AbiMismatch` rejection. Other fixtures also remain
separate from the production generation command.
